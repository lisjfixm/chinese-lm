# 從零打造小型中英字級語言模型（LM 學習專案）

本專案用最少的依賴，從頭實作兩種語言模型，幫助理解「語言模型到底在學什麼」：

1. **n-gram 模型**（純 Python + numpy）：用條件機率與次數統計，原理最透明。
2. **MLP 神經語言模型**（PyTorch CPU）：字向量查表 + 隱藏層，預覽神經網路 LM 的基本骨架。

語料為 `corpus.txt`，共 **200,000 句**，涵蓋繁體中文、英文與少量中英夾雜：

- 真實中文短句：約 120,000 句（取自公開短句語料，OpenCC 簡轉繁）。
- 真實英文句子：約 24,800 句（Tatoeba CC0）。
- 英文模板合成句：30,000 句（主詞 × 動詞 × 賓詞 × 副詞/形容詞組合）。
- 手寫日常短句與問答對話（「問句？—答句。」一行一組）。
- 其餘由中文模板補足；中英夾雜句受模板組合限制，數量很少。

字級（char-level）斷詞，不需要外部分詞套件。英文以小寫字母、空格與標點各自成 token。

## 二、先懂觀念：語言模型在做什麼

語言模型（Language Model, LM）的核心工作，是估計「給定前文，下一個字出現的機率」：

```
P(下一個字 | 前面的文字)
```

有了這個分佈，就能一個字一個字地往下生成句子。

### 2.1 Token（詞元）

本專案把**每一個中文字、英文字母、數字、標點與空格**都當成一個 token。中文沒有空白分詞，字級切分最簡單直觀；缺點是無法表達詞義（例如「開會」「開車」的「開」），進階做法會改用詞級或子詞（BPE）。

特殊 token：

| Token | 意義 |
|---|---|
| `<S>` | 句子開頭，補在句首 |
| `</S>` | 句子結尾，生成時遇到就停止 |
| `<UNK>` | 語料中沒見過的字 |

### 2.2 困惑度（Perplexity, PPL）

用來量化模型對語料的預測能力：

```
PPL = exp( - 平均對數機率 )
```

PPL 越小，表示模型越能預測真實會出現的字；PPL = 詞表大小時，等同於亂猜。

### 2.3 生成時的取樣策略

- **溫度（temperature）**：除以 logits。越低分佈越尖銳、越保守；越高越隨機。
- **top-k**：只在機率最高的 k 個字裡抽樣，減少冷門亂字。
- **循環偵測**：連續三字重複兩次就停止，避免模型繞進同樣的迴圈。

## 三、模型一：n-gram LM

### 3.1 原理

n-gram 假設：下一個字只跟前面 `n-1` 個字有關。

- bigram（n=2）：`P(字 | 前一個字)`
- trigram（n=3）：`P(字 | 前兩個字)`

做法就是在語料中數次數，再算條件機率：

```
P(B | A) = count(A,B) / count(A)
```

### 3.2 兩個實際問題與處理

**稀疏與零機率**：有些組合語料裡沒出現過，直接算會得到 0 機率。使用 **add-k 平滑**，把每個計數先加上常數 k：

```
P(B | A) = (count(A,B) + k) / (count(A) + k × V)
```

**未見過的前文**：trigram 查不到時，退回 bigram，再退回字的邊際頻率（**back-off 階層回溯 + 線性插值**），避免直接掉進幾乎均勻的亂猜分佈。

### 3.3 執行

```bash
python3 ngram_lm.py
# 自訂語料：
python3 ngram_lm.py --corpus 我的語料.txt --n 3 --temperature 0.6 --top_k 5
```

### 3.4 優缺點與本次指標

- 優點：完全可解釋，每個機率都能對應到真實次數；訓練零成本。
- 缺點：上下文視野只有 n-1 個字；資料稍少就非常稀疏；難以表達語義相似性。

本次 20 萬句、詞表 4558，在 5000 句抽樣上的困惑度：

| 模型 | 困惑度 |
|---|---|
| bigram | 87.93 |
| trigram | 74.82 |

相較早期模板語料版本，PPL 明顯變高，這是預期現象：真實新聞短句與英文的用字、搭配遠比固定模板多元，組合更稀疏，模型更難猜中下一個字。trigram 因上下文更長而略優於 bigram。

## 四、模型二：MLP 神經語言模型

### 4.1 架構

```
前 C 個字 id
   │
   ├─ Embedding 查表：每個字對應一個稠密向量
   │
   ├─ 攤平成 C × emb_dim 維度
   │
   ├─ 隱藏層：Linear → tanh
   │
   └─ 輸出層：Linear → 詞表維度 logits → softmax → 下一個字機率
```

對比 n-gram：神經模型用稠密向量表示字與字的關係，語義相近的字會落在相近的向量空間，不會因為「這組合沒背過」就完全失效。

### 4.2 訓練流程

1. 把每句滑動成 `(前文 C 字, 下一字)` 樣本。
2. Cross-Entropy Loss 當目標函式，Adam 優化（weight decay 1e-3）。
3. 樣本過多時隨機取樣上限，避免 CPU 訓練過久；困惑度在抽樣的驗證集上計算。
4. 權重存成 `outputs/mlp_model.pt`，損失曲線存成 `outputs/loss_curve.png`。

### 4.3 執行

```bash
python3 mlp_lm.py
# 可調整：--epochs 4 --ctx 8 --emb 32 --hidden 128 --batch 256
#         --max_train 3000000 --max_val 50000
```

### 4.4 本次實驗觀察（200000 句、詞表 4558）

| 指標 | 數值 |
|---|---|
| 架構 | ctx 8 / emb 32 / hidden 128 |
| 訓練樣本 / 驗證樣本 | 3,000,000 / 50,000（完整資料集為 5.85M / 35.3M，取樣上限內訓練） |
| 訓練輪數 epochs | 4 |
| 訓練困惑度 | 118.73 |
| 驗證困惑度 | 443.33 |
| 參數量 | 766,734 |

驗證困惑度明顯高於訓練集：語料話題與句式多元、模型容量有限，對沒見過的搭配預測能力不足。損失在四輪內下降不多，代表目前規模下再堆輪次收益有限；想壓低 PPL 需要更大的隱藏層、更多資料或換成注意力架構。

### 4.5 生成特性

本地示範生成會出現幾類問題，都符合小型字級模型的預期：

- 中文常見字（「的」「一個」「我們」）主導輸出，句子骨架還算通順，但詞語可能放錯位置。
- 英文因為是字母級建模、且英文語料占比不高，拼字與詞形容易破碎。
- 提示詞稍長或需要語義呼應時，8 字上下文裝不下，容易接成重複的短句。

網頁版預設使用較低溫度與 top-k 取樣，並加上循環偵測，輸出會比本地貪心生成穩一些；仍可能出現少許不通順，這是示範模型的本來限制。

## 六、換自己的語料

1. 把文字整理成一行一句，存成 `corpus.txt` 或另存新檔。
2. 執行時帶 `--corpus 路徑`；若要沿用擴充流程，可修改 `build_corpus.py` 的詞庫與句型後重跑 `python3 build_corpus.py`。
3. 句子越多、句式越多元，模型生成才越自然；目前 20 萬句對神經 LM 仍屬小型示範規模。

## 七、局限與進階方向

目前版本為學習示範，主要局限：

- **資料規模仍小**：真實句占比提高，但模板合成句仍不少；模型對自然語言的覆蓋有限。
- **字級表示**：無法區分詞義歧義；英文以字母建模，拼字與詞形變化處理薄弱。可改成詞級或子詞分詞。
- **上下文很短**：n-gram 看 1–2 字，MLP 看 8 字；真實 LM 用注意力機制看整段前文。
- **正則化有限**：目前只有 Weight Decay；可再加入 Dropout、Early Stopping、學習率調度。
- **中英混雜樣本少**：語料裡真正的夾雜句只有百餘句，模型對 code-switching 的學習很弱。

想再往前一步的路線：

1. 增加英文與中英夾雜語料比例，觀察字母級生成的拼字改善。
2. 把 MLP 換成單層 Transformer（Self-Attention），比較長上下文的表現。
3. 加入詞級分詞或 BPE 子詞，檢視詞表與生成品質的差異。
4. 擴大隱藏層與訓練輪次，配合學習率調度，縮小訓練 / 驗證困惑度的差距。

## 八、網頁示範（單檔 HTML）

```bash
python3 export_model.py   # 匯出 int8 量化權重 + bigram 計數表 → outputs/web_model.json
python3 build_html.py     # 合成 → 活字盤-中英語言模型.html
```

產出的 HTML 完全離線可用：MLP 權重以 int8 對稱量化內嵌（766,734 參數），瀏覽器載入時反量化成 Float32，在 JS 裡重寫前向計算與取樣，不需要任何後端。

網頁內嵌的 n-gram 表只帶 bigram（每個前文保留前 10 個後接字）與 unigram；trigram 全表留在本機 `outputs/ngram_model.pkl`，沒有內嵌進單檔 HTML，以免檔案過大。

頁面包含：首屏即時生成的字盤（每個字上方標出位置序號與字向量二維座標）、生成操作台（溫度 / top-k / 每步機率分佈 / 本次生成困惑度 / **生成軌跡座標圖**：把當前生成字串的 PCA 點依順序連成軌跡）、**個別對話模式**、兩模型同題對照、內部構造與位置說明、**字向量座標圖**（座標取自 Qwen2.5-7B 參考嵌入 3584 維向量 PCA 投影到二維，依中文字 / 英文字母 / 數字 / 標點著色，可搜尋、點選帶入提示詞；Qwen 詞表沒有的生僻字，在自訓向量空間找最近鄰借用其 Qwen 座標）、訓練曲線與困惑度圖。

座標是 PCA 二維投影，只保留兩個主方向；原本的語義關係比這張平面圖更豐富。網頁地圖用的是外部參考嵌入，`模型.txt` 詞表段落附的則是本模型自訓 32 維向量的 PCA 座標，兩者來源不同。

對話模式的做法是「檢索答話」：先比對字的重疊程度，找出語料中最接近的一句問法，交出它對應的答話；沒有相近問法時，才讓模型用「問句 + 破折號—」自己接話。頁面會標出比對到的問法與相似度。之所以不直接用模型生成答案，是因為 8 個字的上下文裝不下整句問答——它接兩三個字就看不到問題了。
