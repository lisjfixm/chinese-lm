# 從零打造小型中文語言模型（LM 學習專案）

本專案用最少的依賴，從頭實作兩種中文語言模型，幫助理解「語言模型到底在學什麼」：

1. **n-gram 模型**（純 Python + numpy）：用條件機率與次數統計，原理最透明。
2. **MLP 神經語言模型**（PyTorch CPU）：字向量查表 + 隱藏層，預覽神經網路 LM 的基本骨架。

語料為內建的 10000 句中文句子（`corpus.txt`）：223 句手寫短句 + 578 組手寫／擴充問答（寫成「問？—答。」一行），其餘約 9200 句由 `build_corpus.py` 以「動作 × 地點 × 人物 × 模板」組合擴充。字級（char-level）斷詞，不需要外部分詞套件。

## 二、先懂觀念：語言模型在做什麼

語言模型（Language Model, LM）的核心工作，是估計「給定前文，下一個字出現的機率」：

```
P(下一個字 | 前面的文字)
```

有了這個分佈，就能一個字一個字地往下生成句子。

### 2.1 Token（詞元）

本專案把**每一個中文字、每一個標點**都當成一個 token。中文沒有空白分词，字級切分最簡單直觀；缺點是無法表達詞義（例如「開會」「開車」的「開」），進階做法會改用詞級或子詞（BPE）。

特殊 token：

| Token | 意義 |
|---|---|
| `<S>` | 句子開頭，補在句首 |
| `</S>` | 句子結尾，生成時遇到就停止 |
| `<UNK>` | 語料中沒見過的字 |

### 2.2 困惑度（Perplexity, PPL）

用來量化模型對語料的預測能力：

```
PPL = exp( - 平均對數機率 )
```

PPL 越小，表示模型越能預測真實會出現的字；PPL = 詞表大小時，等同於亂猜。

### 2.3 生成時的取樣策略

- **溫度（temperature）**：除以 logits。越低分佈越尖銳、越保守；越高越隨機。
- **top-k**：只在機率最高的 k 個字裡抽樣，減少冷門亂字。
- **循環偵測**：連續三字重複兩次就停止，避免模型繞進同樣的迴圈。

## 三、模型一：n-gram LM

### 3.1 原理

n-gram 假設：下一個字只跟前面 `n-1` 個字有關。

- bigram（n=2）：`P(字 | 前一個字)`
- trigram（n=3）：`P(字 | 前兩個字)`

做法就是在語料中數次數，再算條件機率：

```
P(B | A) = count(A,B) / count(A)
```

### 3.2 兩個實際問題與處理

**稀疏與零機率**：有些組合語料裡沒出現過，直接算會得到 0 機率。使用 **add-k 平滑**，把每個計數先加上常數 k：

```
P(B | A) = (count(A,B) + k) / (count(A) + k × V)
```

**未見過的前文**：三gram 查不到時，退回二gram，再退回字的邊際頻率（**back-off 階層回溯 + 線性插值**），避免直接掉進幾乎均勻的亂猜分佈。

### 3.3 執行

```bash
python3 ngram_lm.py
# 自訂語料：
python3 ngram_lm.py --corpus 我的語料.txt --n 3 --temperature 0.6 --top_k 5
```

### 3.4 優缺點

- 優點：完全可解釋，每個機率都能對應到真實次數；訓練零成本。
- 缺點：上下文視野只有 n-1 個字；資料稍少就非常稀疏；難以表達語義相似性。

本次 10000 句語料上的訓練困惑度：bigram 約 6.85、trigram 約 5.72。語料變多之後，同一組前文出現的次數變高，兩者都比 1000 句版本明顯下降。

## 四、模型二：MLP 神經語言模型

### 4.1 架構

```
前 C 個字 id
   │
   ├─ Embedding 查表：每個字對應一個稠密向量
   │
   ├─ 攤平成 C × emb_dim 維度
   │
   ├─ 隱藏層：Linear → tanh
   │
   └─ 輸出層：Linear → 詞表維度 logits → softmax → 下一個字機率
```

對比 n-gram：神經模型用稠密向量表示字與字的關係，語義相近的字會落在相近的向量空間，不會因為「這組合沒背過」就完全失效。

### 4.2 訓練流程

1. 把每句滑動成 `(前文 C 字, 下一字)` 樣本。
2. Cross-Entropy Loss 當目標函式，Adam 優化。
3. 每 5 輪印一次訓練 / 驗證困惑度。
4. 權重存成 `outputs/mlp_model.pt`，損失曲線存成 `outputs/loss_curve.png`。

### 4.3 執行

```bash
python3 mlp_lm.py
# 可調整：--epochs 24 --ctx 8 --emb 32 --hidden 192 --lr 0.01
```

### 4.4 本次實驗觀察（10000 句、詞表 894）

| 指標 | 數值 |
|---|---|
| 訓練樣本 / 驗證樣本 | 156602 / 17159 |
| 訓練困惑度（epoch 24） | 約 4.02 |
| 驗證困惑度（epoch 24） | 約 16.4 |
| 參數量 | 250494 |

擴充語料後，訓練與驗證困惑度的差距明顯縮小，過擬合緩解很多；但驗證困惑度仍高於訓練，表示模型對沒見過的組合預測能力有限。語料多為句型組合、句式偏固定，也是生成變化不多的原因之一。

### 4.5 生成範例（本次執行）

```
「今天」→ 今天，學生在教室問問題。
「早上」→ 早上，媽媽在陽台曬棉被，看起來很安靜。
「天氣」→ 天氣，同學在會議室寫作業。
「媽媽」→ 媽媽炒菜市場的時候，公室顯得很擁擠。
「下班後」→ 下班後，媽媽在陽台曬棉被，看起來很安靜。
```

跟 1000 句版本相比，句子骨架已經穩得多，但仍會出現「詞語被搬到不對的場所」這種語意錯位——這是字級、8 字上下文的模型終究看不清整句結構的結果。

## 六、換自己的語料

1. 把文字整理成一行一句，存成 `corpus.txt` 或另存新檔。
2. 執行時帶 `--corpus 路徑`；若要沿用擴充流程，可修改 `build_corpus.py` 的詞庫與句型後重跑 `python3 build_corpus.py`。
3. 句子越多、句式越多元，模型生成才越自然；目前 10000 句仍屬小型示範語料。

## 七、局限與進階方向

目前版本為學習示範，主要局限：

- **資料規模仍小**：語料由「動作 × 地點 × 人物 × 模板」組合而成，句式偏固定，生成變化有限。
- **字級表示**：無法區分詞義歧義；可改成詞級或子詞分詞。
- **上下文很短**：n-gram 看 1–2 字，MLP 看 8 字；真實 LM 用注意力機制看整段前文。
- **正則化有限**：目前只有 Weight Decay；可再加入 Dropout、Early Stopping、學習率調度。

想再往前一步的路線：

1. 擴充語料到一萬句以上、增加句式與話題多樣性，觀察訓練 / 驗證困惑度的變化（已完成 10000 句）。
2. 把 MLP 換成單層 Transformer（Self-Attention），比較長上下文的表現。
3. 加入詞級分詞或 BPE 子詞，檢視詞表與生成品質的差異。
4. 寫一個簡單的瀏覽器介面輸入提示詞、顯示生成結果（已完成，見第九節）。

## 八、網頁示範（單檔 HTML）

```bash
python3 export_model.py   # 匯出 int8 量化權重 + n-gram 計數表 → outputs/web_model.json
python3 build_html.py     # 合成 → 活字盤-中文語言模型.html
```

產出的 HTML 完全離線可用：MLP 權重以 int8 對稱量化內嵌（250494 參數 → 約 313 KB base64），瀏覽器載入時反量化成 Float32，在 JS 裡重寫前向計算與取樣，不需要任何後端。

頁面包含：首屏即時生成的字盤（每個字上方標出它落在第幾個位置）、生成操作台（溫度 / top-k / 每步機率分佈 / 本次生成困惑度）、**個別對話模式**、兩模型同題對照、內部構造與位置說明、訓練曲線與困惑度圖。

對話模式的做法是「檢索答話」：先比對字的重疊程度，找出語料中最接近的一句問法，交出它對應的答話；沒有相近問法時，才讓模型用「問句 + 破折號—」自己接話。頁面會標出比對到的問法與相似度。之所以不直接用模型生成答案，是因為 8 個字的上下文裝不下整句問答——它接兩三個字就看不到問題了。
